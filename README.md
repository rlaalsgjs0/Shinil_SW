# 팀타임

팀 프로젝트의 시간표, 회의, 과제와 역할을 함께 관리하는 한국어 웹 앱입니다. Node.js 24의 내장 HTTP 서버와 SQLite를 사용하므로 별도 패키지 설치가 필요 없습니다. 브라우저의 `localStorage`에 공동 작업 데이터를 저장하지 않습니다.

## 로컬 실행

1. Node.js 24 이상을 설치합니다.
2. 저장소 루트에서 `node server.mjs`를 실행합니다.
3. `http://localhost:3000`을 엽니다. 다른 기기에서는 같은 네트워크의 서버 IP와 포트로 접속합니다.
4. 테스트: `node --test`

PowerShell에서 `npm` 실행 정책 오류가 나면 위의 `node` 명령을 직접 사용하면 됩니다.

## 설정과 데이터베이스

| 환경변수 | 기본값 | 용도 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 포트 |
| `DB_PATH` | `./data/teamtime.sqlite` | SQLite DB 파일 경로. 첫 실행 시 테이블 자동 생성 |
| `COOKIE_SECURE` | `0` | HTTPS 배포 시 `1`로 설정하여 세션 쿠키에 Secure 속성 적용 |

환경변수는 선택 사항입니다. 개발용 예시 데이터는 자동 생성되지 않습니다. 데이터는 `data/` 아래에 저장되며 Git에서 제외됩니다. 새 DB가 필요하면 서버를 종료하고 다른 `DB_PATH`를 지정하세요. 기존 DB는 안전하게 백업한 뒤 교체하세요.

서비스 표시 이름은 [public/config.js](public/config.js)의 `APP_NAME`만 바꾸면 됩니다. 로딩 중 HTML 제목도 완전히 바꾸고 싶다면 [public/index.html](public/index.html)의 `<title>`을 함께 바꾸세요.

## 주요 동작

- 프로젝트 생성 시 방장 세션, 초대 코드와 개인 복구 코드를 발급합니다. 초대 코드는 참여용이고 복구 코드는 개인 계정용입니다. 서버에는 SHA-256 해시만 저장합니다. 코드는 256비트 난수이며 재표시되지 않으므로 발급 시 보관해야 합니다.
- 초대·복구 요청은 IP별 기본 요청 제한이 있습니다. 세션 쿠키는 HttpOnly, SameSite=Lax로 발급됩니다. 방장은 초대를 재발급하거나 중단할 수 있습니다.
- 탈퇴·제외 확인 후 해당 멤버의 계정, 인증 세션, 복구 정보, 시간표, 개인 설정, 담당 역할, 댓글, 알림과 관련 변경 이력을 영구 삭제합니다. 공동 과제·회의 본문은 유지하며 작성자·대표 담당자·참석자 연결을 제거합니다. 참석자가 없는 확정 회의는 취소됩니다. 삭제한 닉네임으로 재참여해도 새 ID를 발급하고 기존 권한을 복구하지 않습니다. 방장은 멤버 관리의 ‘기존 개인 기록 영구 삭제’로 현재 프로젝트에 남은 이전 방식의 탈퇴·제외 기록을 정리할 수 있습니다.
- 개인 일정, 날짜 예외, 취침·기피 시간, 선택 기간의 빈 시간 확인을 분리합니다. 빈 시간은 확인 전에는 미입력입니다. 일정 제목은 작성자에게만 보이고, 각 일정에서 공유를 선택할 수 있습니다.
- 내 시간표는 00:00~24:00 전체를 1시간 눈금 위의 일정 막대로 표시합니다. 가능은 초록, 불가능·취침은 빨강, 기피는 노랑이며 미입력은 회색입니다. 입력·회의 추천의 기본 단위는 30분을 유지합니다. 반복 요일을 여러 개 선택해 한 번에 등록할 수 있고, 등록 후에는 요일별로 수정·삭제합니다. 모바일에서는 일별 보기와 시간 입력을 제공합니다.
- 시간 입력의 ‘저장’ 옆 ‘선택’ 버튼으로 일괄 삭제 모드를 엽니다. 일정 막대 또는 목록의 체크박스로 여러 일정을 선택하고 ‘선택 삭제’를 누르세요. 반복 일정은 선택한 요일의 모든 주에서 삭제됩니다. 서버에서 본인 소유와 선택 당시 버전을 확인하며, 하나라도 충돌하면 전체 삭제를 중단합니다. 날짜 예외와 빈 시간 확인 범위는 유지됩니다.
- 추천은 회의 전체 길이의 30분 슬롯마다 **같은 사람이 끝까지 가능한지** 확인합니다. 선택한 팀원, 필수 참석자, 전원/최대 인원, 기피 시간, 기간, 주말, TOP N과 중복 구간 제외를 적용합니다.
- 과제는 최대 3단계 트리로 편집하고, 말단 과제에 사람별 역할을 배정합니다. 진행률은 말단 과제의 완료 역할 비율을 평균합니다. 동시 수정은 버전 검사로 409 오류를 반환합니다.
- 회의 확정·시간 변경 직전 현재 시간표와 다른 확정 회의를 다시 검사합니다. 앱은 15초마다 자동 갱신합니다.
- 프로젝트·과제·회의 생성은 요청 ID를 기억해 네트워크 재시도나 중복 제출로 같은 항목이 두 번 만들어지지 않도록 합니다.

## 배포 시 주의

여러 사용자가 같은 서버 URL과 같은 SQLite 파일을 사용하는 **단일 서버 인스턴스**로 배포하세요. 여러 서버 인스턴스를 쓰려면 공유 DB로 이전해야 합니다. HTTPS 역방향 프록시를 두고 `COOKIE_SECURE=1`을 설정하세요. `DB_PATH`는 재시작 후에도 유지되는 볼륨에 두고 정기적으로 백업하세요. 관리자 비밀키가 클라이언트에 들어가지 않습니다.

## 확인된 제약

- 현재 프로젝트 시간대는 `Asia/Seoul`로 고정됩니다.
- 기존 SQLite DB는 서버 시작 시 과제·회의 작성자 연결을 삭제 가능한 구조로 자동 전환합니다. 과제 트리와 다른 데이터는 유지합니다. 범용 버전별 마이그레이션 도구는 아직 없습니다.
- 멤버 영구 삭제는 앱이 관리하는 개인정보와 연결 기록에 적용됩니다. 다른 사람이 공동 문서 본문에 직접 적은 이름, 외부에 보관한 DB 백업이나 이미 열린 브라우저의 사본까지 삭제하지는 않습니다. SQLite `secure_delete`를 사용하지만 저장장치·WAL·백업의 포렌식 삭제를 보장하지 않습니다.
- 이메일, 문자, 외부 메신저 알림은 포함하지 않습니다.
- 이번 작업 환경에 브라우저 자동화 대상이 없어 모바일 실제 기기에서의 터치·레이아웃 조작은 검증하지 못했습니다. 반응형 CSS와 모바일 일별 입력 UI는 구현되어 있습니다.
